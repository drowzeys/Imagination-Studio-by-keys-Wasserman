# Imagination Studio on an NVIDIA GB300 (DGX Station)

The DGX Spark install runs on a GB300: Blackwell Ultra, compute capability 10.3 (sm_103), about 250 GB of HBM on the
card beside the Grace CPU's own memory. The Studio recognises the card from `nvidia-smi` and changes three settings
that were chosen on a Spark's GB10. Everything else is the Spark build. The figures below were measured on one DGX
Station GB300 (driver 595, CUDA 13.2) on 2026-10-27 and 28.

## What you need

| | Minimum | Notes |
|---|---|---|
| GPU | NVIDIA GB300, compute capability 10.3 | A DGX Station also has a small display card; `STUDIO_GPU` names the GB300. |
| CPU and OS | aarch64 (Grace), Ubuntu 24.04 | |
| Driver and CUDA | NVIDIA driver and CUDA 13 as the station ships them | Measured with driver 595 and CUDA 13.2. |
| Disk | As on a DGX Spark, and 5.2 GB more | The fp16 video decoder. |

## Install

```bash
# STUDIO_GPU is the GB300's nvidia-smi index (1 on the station measured: index 0 is its RTX PRO 2000).
# It is needed when the display card is not driving a display, so nvidia-smi lists two compute GPUs.
git clone https://github.com/Keys-Wasserman/Imagination-Studio-by-keys-Wasserman.git
cd Imagination-Studio-by-keys-Wasserman
STUDIO_GPU=1 bash oneshot-setup-rtx-6000.sh
STUDIO_GPU=1 bash scripts/app.sh
```

What the installer does differently on this card:

- **It fetches the fp16 video decoder** (`minimax_h3_video_vae_fp16.safetensors` from Comfy-Org/MiniMax-H3, 5.2 GB)
  beside the 8-bit one.
- **It does not build TensorFold's H3 engine.** Clips render on ComfyUI's own blocks, which are faster on this card.
  `SPARK_ENGINE=tensorfold` builds it anyway; then also set `ENGINE_FROM_SOURCE=1` (the prebuilt engine in the Docker
  image is a GB10's, sm_121, and does not run on sm_103). The build reads the card's compute capability itself;
  `TF_SM=103` forces it.

## What changes on a GB300

| Setting | DGX Spark (GB10) | GB300 | Variable |
|---|---|---|---|
| What runs FastH3's transformer blocks | TensorFold's int8 engine | ComfyUI's own blocks, bf16 | `SPARK_ENGINE` |
| ComfyUI's attention | `--use-ck-attention` | `--use-pytorch-cross-attention` | `SPARK_COMFY_ARGS` |
| Video decoder | 8-bit (`minimax_h3_video_vae_int8_convrot`) | fp16 (`minimax_h3_video_vae_fp16`) | `SPARK_VAE` |

A variable that is set to a value always wins over the card's own setting (an empty one counts as unset). `STUDIO_GPU_PROFILE=default` keeps all three at the
Spark's; `STUDIO_GPU_PROFILE=gb300` gives another card the GB300's. The choice is made in `spark/gpu_profile.py`,
for the card `STUDIO_GPU` names. An install from before this change has no fp16 decoder: its clips decode on the 8-bit
one and the render log says so.

Measured, with the models loaded:

| | GB10's setting | GB300's setting |
|---|---|---|
| Matrix products on the tensor cores | int8: 156 TOPS | bf16: 1,893 TFLOPS |
| FastH3, 864x480, 56 frames | TensorFold int8: 23.3 s (2.42 s a pass) | ComfyUI's bf16 blocks: 9.8 s |
| FastH3, 107 frames, by attention | `--use-ck-attention`: 25.2 s | `--use-pytorch-cross-attention`: 15.5 s |
| Video decode, 864x480, 107 frames | 8-bit: 6.7 s | fp16: 1.3 s |
| A whole clip, 864x480, 107 frames, 4 passes | 12.3 s (8-bit decoder) | about 6.8 s (fp16 decoder) |

PyTorch's attention picks cuDNN's kernel on this card: 2.7 ms a call, where FlashAttention 2 takes 12.1 ms. The int8
engine's kernels are tuned for the GB10, whose int8 products are twice its bf16 ones; on a GB300 bf16 is the faster
path by far.

Memory: the GB300 is a card with its own memory, so a job's room is the card's (as on an
[RTX Pro 6000](rtx-pro-6000.md)), held to the machine's RAM. A clip from references at 1376x768 peaked at about 78 GB.
A clip with a LoRA renders on the bf16 blocks here, and the memory guard holds that route to the largest clip measured
on a Spark (1280x736, 124 frames). The app shows no time estimate on this card, as on other cards with their own
memory: its tables are the GB10's.

## Linux only, for now

The profile is read on Linux. The native Windows CUDA path takes the engine and the video decoder from it too, but its ComfyUI launcher (`spark/comfy_win.py`) keeps its own attention flag; a GB300 on Windows has not been run.
